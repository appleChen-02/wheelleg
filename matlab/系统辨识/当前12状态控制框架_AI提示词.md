# 当前 12 状态控制框架：AI 上下文提示词

> 使用方式：将本文件作为后续 AI 分析、修改 MATLAB 辨识脚本、设计控制器或修改 STM32
> 固件前的上下文。若本文件与源代码冲突，以源代码为准；修改控制逻辑前必须重新阅读文末
> 的源文件。

## 1. 任务与边界

这是一个带尾巴的轮足平衡机器人。当前有效控制器是**尾巴离地、双轮接地、小扰动附近**
的 12 状态、5 广义输入 LQR。LQR 外部仍有腿长轴向力前馈/PID、VMC 和实体电机命令
处理；部分航向/尾巴附加 PID 只在其它模式或特定代码路径中生效，不能笼统地当作当前
辨识对象的五维 LQR 输入。

当前目标是：

- 在固定工作点附近采集无激励、正弦扫频或 PRBS 数据；
- 先辨识当前的 12 状态、5 输入模型；
- 使用辨识模型校正或替代现有模型，再设计新的控制器；
- 后续可能扩展为 18 状态、7 输入，但该控制器**尚未实现**。

不要假设当前已经存在 18 状态控制器。固件中的 18 状态、7 输入 USB 帧、参数和部分数据
字段仅是协议预留；当前实际闭环计算仍是 12 状态、5 输入。

## 2. 运行时控制链

底盘任务周期由 `CHASSIS_CONTROL_TIME_MS` 定义，目前为 2 ms，即名义 500 Hz。每个周期的
顺序为：

```text
ChassisObserver
  -> 更新电机、IMU、五连杆运动学、速度观测器和状态
ChassisHandleException
  -> 离线/IMU/关节异常处理
ChassisSetMode
  -> 根据遥控器开关选择模式
ChassisReference
  -> 生成参考状态和腿长/尾巴参考
ChassisConsole
  -> LQR、附加控制、腿长 PID、VMC，生成电机命令
ChassisSendCmd
  -> CAN 发送关节、轮子、尾巴电机命令
```

系统辨识模式由 **CH5 与 CH8 同时上档**进入，枚举值是
`CHASSIS_SYSTEM_IDENTIFICATION`。该模式复用尾巴离地双足控制路径
`ConsoleBipedal -> LocomotionController_Pro_Bipedal -> LegTorqueController`，并不是一个
独立的新控制器。

## 3. 坐标、腿和电机约定

### 3.1 左右腿索引

```text
leg[0] = 左腿
leg[1] = 右腿
```

物理电机与 `motor_torque[7]` 的固定顺序：

```text
0 = J0，左腿前关节
1 = J1，左腿后关节
2 = J2，右腿前关节
3 = J3，右腿后关节
4 = W0，左轮
5 = W1，右轮
6 = Tail，尾巴
```

电机反馈力矩当前来自 iq 换算。系统辨识的第一阶段暂时将其视作真实输出轴力矩，但后续应
单独标定减速比、效率、摩擦和电流环误差。

### 3.2 虚拟腿变量

每条五连杆腿先由关节角解算为虚拟杆变量：

```text
L0       虚拟杆长，m
dL0      虚拟杆长速度，m/s
Phi0     虚拟杆在机体/机构定义坐标中的角度，rad
Theta    腿摆角
F        沿虚拟杆轴向力，N
Tp       虚拟腿摆动/髋关节广义力矩，N*m
```

`body.phi` 与 `body.phi_dot` 在当前代码中等同于 IMU 的 `pitch` 与 `pitch_dot`。

## 4. 当前 12 状态模型

当前有效状态顺序固定为：

```text
index  name              单位    当前来源
0      body_x            m       body.x（速度观测积分）
1      body_x_dot        m/s     body.x_dot_obv（卡尔曼速度观测器）
2      yaw               rad     IMU yaw
3      yaw_dot           rad/s   IMU yaw rate
4      left_theta        rad     左腿 leg_state[0].theta
5      left_theta_dot    rad/s   左腿 leg_state[0].theta_dot
6      right_theta       rad     右腿 leg_state[1].theta
7      right_theta_dot   rad/s   右腿 leg_state[1].theta_dot
8      pitch             rad     body.phi == body.pitch
9      pitch_dot         rad/s   body.phi_dot == body.pitch_dot
10     tail_beta         rad     tail_state.beta
11     tail_beta_dot     rad/s   tail_state.beta_dot
```

控制器内使用的误差状态并不只是 `feedback - reference`：还会叠加 `X0_OFFSET` 至
`X11_OFFSET`，yaw 误差使用 `WrapToPi`。修改状态定义、参考定义、偏置或上位机解释时，
必须保证与 `LocomotionController_Pro_Bipedal()` 完全一致。

系统辨识模式下参考来自
`单片机/application/robot_param/system_identification_param.h`：

- 纵向位置、速度、yaw、yaw 角速度；
- 左右腿角与角速度；
- pitch 与 pitch 角速度；
- 尾巴角与角速度；
- roll 参考和左右腿长参考也会被保存，用于后续 18 状态协议预留；
- 左右腿 `theta` 参考在控制器内还会叠加随腿长插值的 `theta_eq`。

因此系统辨识参考帧中输出的是**控制器实际使用的参考**，不应在上位机仅依赖参数文件宏
自行重建。

## 5. 当前 5 个广义输入

当前 12 状态 LQR 的输入顺序固定为：

```text
index  name              单位    写入的控制变量
0      Tp_right          N*m     cmd.leg[1].rod.Tp
1      Tp_left           N*m     cmd.leg[0].rod.Tp
2      T_wheel_right     N*m     cmd.leg[1].wheel.T
3      T_wheel_left      N*m     cmd.leg[0].wheel.T
4      T_tail            N*m     cmd.tail.Tt
```

它们是**广义输入，不是五个实体电机力矩**。四个关节电机由两腿各自的 `[F, Tp]` 经 VMC
映射得到，轮和尾巴再经方向变换后发送给实体电机。

当前平衡前馈输入由 `GetT0_Pro_Bipedal()` 给出：

```text
u_equilibrium = [Tp_eq, Tp_eq, 0, 0, Ttail_eq]
```

当前 LQR 计算函数是 `CalcLQR_Pro_Tail()`。其符号由手写展开式决定，不能在 MATLAB 或
上位机中假设它一定等于简单的 `-K*x` 或 `K*x`；如需复现固件，必须逐项对照该函数。

在系统辨识模式中，对五维 LQR 广义输入的理论分解为：

```text
u_command_5 = u_lqr + u_equilibrium + u_excitation
```

其中 `u_excitation` 由正弦扫频或 PRBS 叠加到五维 LQR 输出后、VMC 映射前。四个关节
电机的 VMC 输入还包含当前 12 状态 LQR 未输出的 `F_left/F_right`，因此不应将实体电机
反馈与上述五维命令的差异简单解释为执行器跟踪误差。

## 6. 腿长、roll 与 VMC：当前不属于 12 状态 LQR 的部分

当前 12 状态 LQR 不直接输出左右腿轴向力 `F_left/F_right`，它们由
`LegTorqueController()` 独立生成：

```text
F_leg = 重力前馈 LegFeedForward(theta)
      + 腿长 PID 输出
      + roll 相关补偿
```

系统辨识模式下，腿长参考保持固定；但腿长 PID 和重力前馈仍然参与实际关节力矩生成。
因此当前 12 状态模型的五维输入无法完全代表所有实体关节力矩的来源，腿长子控制是一个
未被纳入 LQR 状态/输入的耦合控制环。

左右腿 `[F, Tp]` 到两个关节广义力矩的 VMC 关系由 `CalcVmc()` 定义：

```text
[T1, T2]^T = J^T * [F, -Tp]^T
```

代码实现对 `Tp` 使用显式负号。由实际关节力矩反算虚拟力时使用 `GetLegForce()`；其输出
第二项需要再取负才与当前 LQR 的 `Tp` 符号一致：

```text
[F, temp]^T = GetLegForce(J, T1, T2)
Tp_actual = -temp
```

反算必须检查雅可比行列式。接近机构奇异位形时，不能把反算得到的大值当作可靠实际输入。

## 7. 其他闭环补偿与系统辨识路径

代码中存在以下附加控制环或模式相关处理：

- roll 控制：在有些模式中根据腿长差和 roll 误差协调左右腿长参考；
- 腿长 PID：输出每条腿的轴向力补偿，当前双足路径中仍参与 VMC；
- 航向速度 PID：代码中对部分工作模式的左右轮施加差动附加力矩，分析辨识数据时必须
  以当前实际模式和源代码执行路径为准；
- 尾巴 pitch/触地补偿：主要出现在尾巴触地或其它模式路径，不能默认属于当前尾巴离地
  12 状态 LQR；
- 五连杆 VMC 映射；
- 实体电机方向变换、软件限幅及驱动器电流限幅。

系统辨识模式实际调用：

```text
ConsoleBipedal
  -> LocomotionController_Pro_Bipedal
  -> LegTorqueController
  -> 实体电机方向变换与 CAN 发送
```

在该模式下，12 状态 LQR 计算五维 `Tp/Twheel/Ttail`；激励叠加在这五维输出之后、VMC
之前。腿长参考保持固定，普通模式中的腿长差参考协调不执行，但
`LegTorqueController` 仍计算轴向力前馈和腿长 PID，再与 `Tp` 一起进入 VMC。
这条轴向力通道没有纳入当前 12 状态 LQR 的独立输入，是辨识时必须说明的耦合闭环。

因此，真实闭环不是纯粹的 `u = Kx`。在分析无激励数据或辨识结果时，应区分：

```text
controller_output       当前 LQR 输出（5维）
equilibrium_input       LQR 平衡前馈（5维）
excitation              外部激励（5维）
generalized_command     VMC 前最终广义命令（5维）
motor_feedback_torque   7 个实体电机反馈力矩
generalized_actual      由实体反馈和 Jacobian 反算的等效广义输入
```

`generalized_command` 与 `generalized_actual` 的差异既可能来自执行器动态，也可能来自 VMC、
限幅、摩擦、反馈力矩标定误差和未记录的附加控制环。

## 8. 系统辨识模式与激励

系统辨识参数文件：

```text
单片机/application/robot_param/system_identification_param.h
```

当前关键配置应以该文件实际内容为准。通常需要关注：

```text
SYS_ID_OUTPUT_PROFILE          当前应为 12_STATE_5_INPUT
SYS_ID_EXCITATION_ENABLE       0=无激励，1=允许激励
SYS_ID_EXCITATION_MODE         SINE_SWEEP 或 PRBS
SYS_ID_EXCITATION_INPUT_MASK   bit0~4 对应当前五个广义输入
```

对于 12 状态 profile，固件会屏蔽 bit5/bit6，避免未来预留的左右腿轴向力激励污染当前
5 输入辨识实验。

激励实验的顺序建议：

```text
1. 无激励：确认工作点、漂移率、闭环稳态波动和 LQR 输出噪声
2. 单通道小幅正弦扫频：先检查线性范围与共振
3. 单通道 PRBS：获得宽频动态
4. 多通道独立 PRBS：用于 5 输入 MIMO 辨识
```

不要在未验证单通道稳定性前启用多通道大幅值激励。

## 9. 系统辨识 USB 协议

普通模式继续使用原有 USB 帧。进入系统辨识模式时，普通周期帧暂停，仅保留电机错误帧，
并发送专用帧：

```text
0x10  12 状态 / 5 输入高速采样帧，250 Hz（4 ms）
0x11  18 状态 / 7 输入高速采样帧，协议预留，当前不要作为控制器依据
0x12  参考配置帧，1 Hz，进入模式后优先发送
```

`0x10` 高速帧包含：

```text
control_tick_ms, sequence, experiment_id, reference_sequence
protocol_version, profile_id, state_dimension, input_dimension
excitation_config, excitation_input_mask, status_flags, motor_saturation_mask
state_feedback[12]
controller_output[5]
excitation[5]
generalized_command[5]
generalized_actual_torque[5]
motor_feedback_torque[7]
```

`0x12` 参考配置帧包含：

```text
experiment_id, reference_sequence
profile/version/dimensions/excitation configuration
state_reference[18]       当前 12 状态时只使用前 12 项
equilibrium_input[7]      当前 12 状态时只使用前 5 项
```

数据处理时：

- 使用 `control_tick_ms` 作为时间轴，不使用 PC `host_time_s` 做辨识时间轴；
- 使用 `sequence` 检测控制周期跳帧；
- 用 `experiment_id + reference_sequence` 关联高速帧与参考帧；
- 仅使用 `profile_id=1, state_dimension=12, input_dimension=5` 的数据进行当前模型辨识；
- 剔除或标记 `status_flags` 中电机离线、雅可比异常、实际输入无效的样本；
- 单独处理 `motor_saturation_mask != 0` 的样本，不能默认其输入未受限幅影响。

上位机记录器输出：

```text
system_identification_12.csv
system_identification_reference.csv
```

MATLAB 无激励分析入口：

```text
matlab/系统辨识/analyze_sysid_no_excitation.m
```

## 10. 无激励基线实验

无激励实验的目的不是估计纯传感器噪声，而是测量固定工作点附近的**闭环稳态波动**。它包括：

```text
传感器噪声 + 机械振动 + 执行器纹波 + 地面扰动 + 观测器误差 + LQR闭环响应
```

无激励时应设置：

```c
SYS_ID_EXCITATION_ENABLE = 0U
```

分析应至少得到：

- 12 状态和 5 个控制输入的均值、中位数、标准差、AC RMS、峰峰值、分位峰峰值；
- `body_x`、展开后的 yaw 及速度的漂移斜率；
- `state_feedback - state_reference` 的工作点偏差；
- `controller_output` 的均值和协方差，识别持续模型补偿与 LQR 噪声放大；
- 状态、输入和状态-输入协方差/相关性；
- PSD，至少检查 0--1 Hz、1--20 Hz 和更高频段。

不要无记录地去除漂移。需要同时保留原始量、拟合趋势、斜率和去趋势残差。

## 11. 未来 18 状态 / 7 输入扩展

未来计划是增加：

```text
roll, roll_dot,
left_leg_length, left_leg_length_dot,
right_leg_length, right_leg_length_dot
```

得到 18 状态。建议新增广义输入为：

```text
F_left, F_right
```

形成 7 输入：

```text
[Tp_right, Tp_left, T_wheel_right, T_wheel_left, T_tail, F_left, F_right]
```

这项扩展需要重新建立/辨识完整模型并重新设计控制器。不能将当前 12 状态 K 矩阵简单补零后
继续使用；同时必须重新处理现有腿长 PID 和 roll 子控制，避免两个控制器对 `F_left/F_right`
重复作用。

## 12. 给 AI 的工作规则

当被要求修改本项目时，请遵守：

1. 先确认当前处理的是尾巴离地双足 12 状态路径，而不是尾巴触地或无尾模式。
2. 不改变状态、输入、左右腿、电机或符号顺序，除非同时更新固件、USB 协议、Python 和 MATLAB。
3. 不将 `motor_feedback_torque` 自动视为严格输出轴真实力矩；当前仅是临时辨识假设。
4. 不在未检查 VMC Jacobian 行列式、实体电机限幅和状态标志时相信反算广义输入。
5. 不把 18 状态协议预留误认为现有控制器能力。
6. 不将 `controller_output`、`equilibrium_input`、`excitation` 或最终命令混为同一个量。
7. 对所有辨识数据优先使用 MCU `control_tick_ms` 和 `sequence`；PC 到达时间只用于日志诊断。
8. 修改控制器前，先评估当前无激励基线、饱和、漂移和实际输入跟踪误差。
